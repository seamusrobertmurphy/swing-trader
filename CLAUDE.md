## Principles

These are the priors that shape every decision. Hard rules below operationalise them. Where a rule is silent, principles decide. Full derivation and citations live in `research/synthesis-quant-methods.md` and `research/authoritative-references.md`.

1.  **Edge must be demonstrable.** Before any new position, write a one-paragraph affirmative case and a one-paragraph devil's advocate against it in `research-log.md`. If the rebuttal stands, the trade does not. The act of trying and failing to break the thesis is the evidence of edge (Thorp; Buffett).

2.  **Size by Kelly, then halve.** The Kelly fraction is f\* = (p·b − q) / b, where p is the agent's honest win probability, q = 1 − p, and b is the reward-to-risk ratio set by the 10% trailing stop against the 7% hard stop. Use half of f\* when all entry signals fire, a quarter when only the minimum count fire. The 5% notional cap is a ceiling, not a default. Kelly inputs go in the entry log so the Friday review can grade them.

3.  **Tails are fatter than the model.** Geometric Brownian motion understates real-world gaps. The 7% hard stop protects against trends, not against earnings gaps or regulatory shocks. Size every position so that a 15% adverse overnight gap on it alone does not trip the 3% daily circuit.

4.  **Drawdowns shrink the book, not just block it.** Below a 5% rolling-week drawdown on the book, begin reducing new-position size 1:1 with each further 1% of drawdown. The binary 3% intraday circuit remains. Recovery reverses the ramp.

5.  **No anchoring.** Cost basis is a number in a ledger. Hold and sell decisions reference forward expected value only. Cost basis is used only to compute the 7% hard stop, to compute realised P&L for the journal, and (when live) for tax accounting.

6.  **Filter the noise.** SPY's expected daily move is approximately VIX / √252. Headlines explaining moves smaller than that explain nothing and do not justify action. Single-name moves are compared against the name's own implied volatility where available, otherwise against 1.5× the SPY expected move.

7.  **Correlation budget.** Compute a 60-day pairwise correlation matrix over holdings each Friday. The aggregate weight of any cluster with ρ \> 0.7 is capped at 20% of equity. This sits in addition to the 30% GICS-sector cap; the sector cap catches obvious concentration, the correlation cap catches the case where two different sectors move together.

8.  **Fat pitches override the cap, never the principles.** A documented dislocation may stretch one position to 10% of equity (double the normal cap). The entry must record, in the same trade-log line, an asymmetric R:R of at least 3:1, a named structural cause for the dislocation, and a written exit condition. Without all three, the cap stays at 5%.

9.  **Lognormal arithmetic.** Multi-month return projections compound in log space. The Friday review reports geometric and arithmetic mean returns separately, with the variance drag σ²/2 as an explicit line item.

10. **Cross-check, don't worship.** Every new-position write-up triangulates among at least two of peer-group multiple (EV/EBITDA, P/FCF), owner-earnings yield versus the 10-year Treasury, and replacement-cost or sum-of-the-parts. Single-method valuations are flagged for additional scrutiny.

11. **Factor tilts compound silently.** The Friday review estimates the book's coarse value, momentum, quality, and size tilts against SPY. Absolute tilts above 0.3 are flagged and resolved in the next two weeks of entries.

## Hard rules (non-negotiable)

-   No real orders until `LIVE_TRADING=true` is set in the environment; treat any other value, including unset, as `false`. There is no paper endpoint for crypto: until the switch is armed the agent runs against the Binance testnet (`BINANCE_TESTNET=true`) or just reads the market without placing orders.
-   Max position size: 5% of portfolio equity at entry, hard ceiling. The default size inside that ceiling is half-Kelly (Principle 2); a quarter-Kelly default applies when only the minimum count of entry signals fire. Kelly inputs (p, b, f) are written into the entry log.
-   Fat-pitch exception: one position at a time may be stretched to 10% under Principle 9. The trade-log entry must record asymmetric R:R ≥ 3:1, a named structural cause, and a written exit condition. Failure of any of the three reverts the cap to 5%.
-   Daily loss cap: if realised plus unrealised drawdown over a rolling 24 hours exceeds 3% of the window-start equity, halt new orders until the window resets and record it in the journal. Existing stops continue to operate. (Crypto trades 24/7, so the cap is measured over a rolling 24-hour window, not a calendar day.)
-   Drawdown sizing ramp: when the rolling 5-day book P&L is below −5%, reduce the default new-position size 1:1 with each further 1% of drawdown. Recovery reverses the ramp. The 3% intraday circuit sits on top.
-   Gap-risk margin: size every entry so that a 15% adverse move on it alone does not by itself trip the 3% daily circuit. (Crypto has no overnight gap as such; it can move that far within a day, so the margin guards against a single sharp move.)
-   Anchoring prohibition: never reference cost basis in hold or sell logic. Cost basis is used only to compute the 7% hard stop, to record realised P&L, and (when live) for tax accounting.
-   Never short. Never options. Never margin. On Binance, spot only — never futures, never margin, never leveraged tokens.
-   Spot crypto trades live on Binance and spends real funds; `inputs/trade_binance.py` refuses to place, replace, or cancel an order unless `LIVE_TRADING=true` is set in the environment for that run. This is the single deliberate switch between reading the market and moving real money on Binance.
-   Never average down. A losing position is exited or held; it is not added to.
-   Hard stop: exit any position trading −7% below cost basis. Treat this as a trend-protection rule, not a gap-protection rule; sizing carries the gap case. (Provisional: the code today uses a 5% stop on the model label and an ATR stop averaging about 8.5%, so the 7% here is a placeholder until the exit-geometry tuning reconciles them.)
-   Trailing stop: 10% from peak on any winner. Set as a server-side trailing-stop order on Binance where possible. (Provisional: the 10% is a placeholder until the exit-geometry tuning settles it.)
-   Cash floor: keep at least 10% in cash unless an entry meets the Principle 9 fat-pitch conditions or at least three of the four entry signals fire on a single name; document the override in the trade-log entry.
-   Max 3 new positions per week.
-   If a run is uncertain, do nothing and journal the uncertainty. (The journal and memory file layout is not yet settled, so repoint this to the chosen file once it is.)
-   Read memory before acting. Commit memory before exiting; without the commit, the next run is blind. (The `memory/` files do not exist yet, so this takes effect once the memory layout is built.)

## Data and model design (hard rules, 1h all-market frame; added 2026-06-21)

Adopted 2026-06-21 and non-negotiable going forward. They supersede the earlier fixed-ten daily design for the model track. The June-21 session handover supersedes the June-20 one for all task directives. Derivation and compliance live in `tasks/data-standards.md` and `tasks/build-decisions-2026-06-21.md`.

-   Universe and frame: train on the FULL active USDT spot market (~433 pairs from Binance `exchangeInfo`), point-in-time screened per bar, on 1-hour OHLCV bars. Not the fixed ten. The daily `inputs/build_dataset.py` is kept but superseded; the model frame is `inputs/build_dataset_1h.py`.
-   History: download and use the LONGEST history available per coin (BTC back to 2017). The "2 years training, 1 year out-of-sample" figures are minimums a coin must clear, never caps. History is never truncated.
-   Source: exchange-grade only. Primary source is the official `data.binance.vision` archives (exchange-direct, deterministic, and they carry the taker-buy flow ccxt drops). ccxt is a live top-up/fallback for the still-forming bar only, never the primary feed. The build is offline and reproducible.
-   Storage: datasets and the flow table are stored as Parquet (columnar, compressed, dtype-preserving), CSV is a fallback only. `build_dataset_1h.read_frame`/`write_frame` prefer the `.parquet` sibling and fall back to `.csv`; `--csv` writes a CSV companion alongside. Parquet is mandatory because round-tripping timestamps through CSV silently changed dtypes (`datetime64` → `str`) and broke the train/test split on load; Parquet preserves column types so the split is reliable without re-parsing. Measured: `dataset_1h_allmarket` 645MB CSV → 250MB Parquet (~2.6x), `flow_1h` 1148MB CSV → 437MB Parquet, both loading in seconds.
-   Data quality: every coin passes a gap gate before training — at most 2% of expected hourly bars missing and no single gap over 72 hours — because the features assume regularly spaced bars. Coins that fail are excluded.
-   Features: an in-house baseline plus OPTIONAL pandas-ta and TA-Lib breadth layers. Two window families on every coin — a wall-clock family (the daily windows times 24) and a shorter intraday family — plus in-house extra indicators (Williams %R, Stochastic, CCI, CMF, MFI, ADX/DMI, Aroon), the trade-flow imbalance, an optional pandas-ta block (PPO, TRIX, Vortex, CMO, Fisher, Chande Kroll Stop), and an optional TA-Lib block curated to what it uniquely adds (Parabolic SAR and MESA-MA distances, Ultimate Oscillator, Hilbert-transform cycle features, and a candlestick-pattern family) — not all 158 TA-Lib functions, since most duplicate the above. The in-house baseline always computes, so the pipeline never hard-depends on either library. Every feature is causal and scale-invariant; breadth is candidate-only and the after-fee out-of-sample scoreboard is what prunes. The 1h pipeline runs from the project `.venv` (MacPorts python; pandas-ta and TA-Lib are pip-installed there — TA-Lib via a prebuilt wheel — never into the MacPorts root-owned system packages, which is what blocked the bare system install).
-   Label: a configurable, ATR-scaled triple barrier on a shorter day-trade horizon. Default is +2 ATR before -1 ATR within 48 bars (2 days); target, stop, and horizon-in-bars are swept in Priority 1b. This replaces the inherited +10% / -5% / 20-day label for the 1h frame.
-   Point-in-time screen: liquidity (trailing 24h quote volume >= 30M USDT), an ATR band recalibrated to 1h, history, and spread APPROXIMATED by a Corwin-Schultz high-low estimator because klines carry no top-of-book spread. The live screen still uses the real spread.
-   Split and scoring: hold out the final ~1 year out-of-sample, train on all prior history, embargo equal to the label horizon, and score the test set once. Keep only changes that beat both buy-and-hold and a coin-flip on the out-of-sample, after-fee scoreboard.
-   Exit geometry: the tuning sweep adds per-coin/per-split trailing stops and a time-decaying take-profit, scored on the same after-fee scoreboard; reconcile the three forked exit configs once the sweep settles. The -7% hard stop and 10% trail above remain provisional pending that sweep.

## Commit discipline

Every run ends with:

```         
git add -A
git commit -m "<routine>: <one-line summary>"
git push origin main
```

If the working tree is clean (no decision, no trade, no observation worth journaling), the routine still writes a one-line dated entry to `memory/research-log.md` so there is always a heartbeat commit.

## Notification discipline

-   pre-market: silent unless a catalyst is urgent or research surfaces a thesis-break on an existing holding.
-   market-open: notify only if a trade is placed.
-   midday: silent unless a stop fires or a position is cut.
-   market-close: always post EOD summary to ClickUp.
-   weekly-review: always post the full review to ClickUp.

ClickUp format is defined in `skills/notify.md`.

## When in doubt

Do nothing. Journal the hesitation in `memory/learnings.md` with the date, the symbol or situation, and why you stood down. The user reads `learnings.md` weekly. A skipped trade that turns out to be right is fine; an undocumented skip is not.

## Notebook integration (authoring convention; added 2026-06-23)

Operator directive: the helper scripts in `inputs/` are to be cleaned up and shortened so their essential logic integrates directly into the chapter notebooks, rather than the notebook calling out to long modules. The notebook is the deliverable; a reader should see the key code and data operations inline, not a one-line call into a 600-line script. When wiring a capability in, prefer lifting the readable core into a notebook cell (or a short, notebook-friendly helper) over importing the whole module. This relaxes the earlier "knobs live in the scripts so the notebook cannot drift" stance: keep a single source of truth for heavy or duplicated logic, but each notebook must stand on its own as a legible demonstration of every key operation, and any script that remains is trimmed to what the notebook actually needs.
