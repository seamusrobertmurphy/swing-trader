# Repository audit, 8 September 2026

Dead code, dropped features and stale references, found by reading every file
rather than by reading the file names. Each finding below names the artefact it
rests on and was re-run against the tree at the moment of writing.

## Method

Every text file outside `.venv`, `.git` and the Jupyter cache was read into one
corpus, 482 files. Each of the 62 modules in `03-inputs/` was then searched for
across that corpus, so a module with no importer and no caller anywhere is
reported as an orphan rather than assumed to be one. Documented file paths in
`README.md`, `CLAUDE.md`, `INDEX.md` and `02-runtime/trader-workflow.qmd` were
checked against the disk. Shell scripts were read for paths the September
reorganisation moved. `ruff --select F401,F841,F811` was run over the live code.

## Fixed in this pass

### The scheduler had been dead for twelve days

`~/Library/LaunchAgents/com.daytrader.tick.plist` pointed at
`/Volumes/PortableSSD/Github/day-trader/scripts/tick.sh`. The reorganisation
moved that file to `05-research/scripts/tick.sh`. `launchctl list` reported exit
status 127 and `~/Library/Logs/daytrader/tick.log` held 102 consecutive lines
reading `No such file or directory`. Nothing rebalanced, reported or checked the
catastrophe stop automatically in that window. The book's last rebalance was
27 August, eleven days before this audit, against a seven-day cadence.

`05-research/scripts/install_schedule.sh` would not have fixed it either. It
carried four stale paths of its own, `$REPO/scripts/schedule`,
`$REPO/inputs/config.py` and two references to `$REPO/scripts/tick.sh`, so a
reinstall would have written a correct plist and then failed its own
verification. All repaired, the job reinstalled, and a whole tick now runs from
a shell.

One blocker remains and it is not a code fault. macOS refuses a background job
read access to a removable volume, so the installer's own probe reports
`PROBE_READ_BLOCKED`. Granting Full Disk Access to `/bin/bash` clears it. Until
then the schedule is registered and will not run.

### Five shell scripts wrote to a folder that no longer exists

`tick.sh`, `daily_report.sh`, `run_forever.sh` and `weekly_rebalance.sh` all
built log paths as `$REPO/outputs/AA-evals/...`, the pre-reorganisation name.
They had not yet created a stray `outputs/` at the repository root only because
none of them had run. `weekly_rebalance.sh` also read its cadence guard from
`$REPO/memory/alpaca-book-state.json`, a path that does not exist, so the guard
that prevents a too-early rebalance was silently passing. `set_credentials.sh`
called `$REPO/inputs/alpaca_check.py`. All seven repaired.

### The model assessment crowned a model its own rule rejects

`03-inputs/model_assessment_1h.py` selected the best model by cross-validated
error alone and never consulted the overfit ratio. On
`04-outputs/AA-evals/2026-09-06/model-assessment-20260906.md` that picked
HistGBM at a ratio of 1.840 against a house bar of 1.1, then scored the blind
year with it. Selection now runs inside the set that passes the bar, through a
single `pick_best`, and the record states plainly when no model passes at all.
On the 6 September numbers the pick becomes the random forest at 1.069.

The tuner had the same defect and worse. `tune()` computed only the
cross-validated error, never the training error, so the overfit ratio did not
exist for a tuning grid and the house rule could not be applied to it. The
training fit is now computed per grid point and both the record and the console
line report the ratio and the verdict.

### Section 3.8 of the workflow rendered as an empty heading

Every line of the only code chunk in Model Tuning was commented out, including
the `display(Markdown(...))` that was meant to render the scoreboard. The
section produced a heading and nothing else. It now reads every tuning record on
disk through `model_metrics.read_tuning_records` and prints the grid with a
per-row verdict.

### The selectivity charts were missing from every render since 7 September

`model_metrics.absolutise_images` rewrote a record's image link to an absolute
path. Quarto reads a leading `/` in a markdown image as relative to the
document, so `/Volumes/...` was looked for at `./Volumes/...`. The render still
succeeded and printed one WARNING line among hundreds. Reproduced on 8 September
with a two-line test document in which the same image resolved under a `file://`
URI and failed as a bare absolute path in the same render. The function now
emits `file://` URIs.

A second lesson sits on top of it. The fix did not reach the page on the next
render, because Quarto caches a cell on its own text and the text had not
changed. A dated comment in the cell forced the re-execute.

### The Word table formatting had been dropped

`03-inputs/format_docx_tables.py` was written on 7 September on operator
instruction to give every table one shape, which Quarto cannot do. Nothing has
called it since. Every Word render since that date shipped with tables sized to
their own content. A new `05-research/scripts/render_workflow.sh` renders both
formats, sets `QUARTO_PYTHON` to the project venv, and applies the table pass.

### Removed

`03-inputs/render_workflow_docx.py`, which rendered the old `.ipynb` to Word and
is superseded by Quarto's own docx format. Nothing referenced it. 49 AppleDouble
`._` files, one of which was `03-inputs/._model_metrics.py`, a 4 KB binary
carrying a `.py` extension beside the real module.

## Open, not acted on

### The runtime scaffold in INDEX.md was never built

`INDEX.md` lists `routines/pre-market.md`, `routines/market-open.md`,
`routines/midday.md`, `routines/market-close.md` and
`routines/weekly-review.md`. There is no `routines/` directory anywhere in the
tree and git records no commit that ever added one. It also lists
`05-research/memory/strategy.md`, `learnings.md` and `weekly-review.md`, and
`05-research/scripts/alpaca.sh`, `bootstrap.sh`, `clickup.sh` and
`perplexity.sh`. None exists. `CLAUDE.md` describes a five-routine cadence and
states that the operator reads `learnings.md` weekly.

### The narrow book gates on a file that is absent

`03-inputs/narrow_book.py` writes `05-research/memory/narrow-book.json` and
`03-inputs/trade_binance.py` refuses entries outside it. The file does not
exist.

### Every model is trained against the metric it is scored on

All seven models in the zoo are built with `class_weight="balanced"`, which
pushes predicted probabilities away from the true base rate, while the headline
metric is the Brier score, which measures exactly that distance. There is no
calibration step anywhere in the repository, no reliability curve and no Platt
or isotonic fit.

### Two vendored scripts nothing calls

`03-inputs/binance-scripts/download-aggTrade.py` and `download-trade.py` are
Binance's own public downloaders, superseded by `acquire_vision.py`. Nothing in
the corpus references either. They carry the only five ruff findings in the live
code, all unused imports.

### The findings section is stale and omits the equity result

Section 5 of the workflow quotes figures dated 17 August and does not mention
equities. The only strategy that ever cleared the bar is absent from the
document's own findings.

### The evidence tree has no equity folder

`04-outputs/` numbers its folders `1A` through `3D` and every one of them is
crypto. The equity records live scattered through `AA-evals/` by date.
